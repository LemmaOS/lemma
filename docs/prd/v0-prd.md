# Lemma — PRD（产品需求文档）

> 版本：v0.5 | 状态：评审中（开放问题已全部对齐）
> 文档只保留当前状态，历史变更由 git 提交记录承载。

## 1. 背景与目标

构建一个开源自部署的 AI 对话助手，包含服务端、Web 端、桌面端和移动端。作者自用起步，同时开源给有同样需求的用户自行部署。

**目标：**

- 个人拥有数据主权：服务自己部署，对话数据存在自己的服务器上
- 全端覆盖：任何设备上都能用，且数据互通
- 开源可复现：别人 clone 下来能轻松部署自己的实例

## 2. 目标用户

- 首要用户：作者本人（日常 AI 对话使用）
- 次要用户：有自部署能力、注重数据隐私的开源用户（个人或小团队）

## 3. 产品形态

| 端     | 技术方案                                                  | 说明                                                                                    |
| ------ | --------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 服务端 | Rust                                                      | 自部署，对外提供 API                                                                    |
| Web 端 | React                                                     | 浏览器直接使用，与桌面端共用代码                                                        |
| 桌面端 | Electron（React 套壳）                                    | Windows / macOS / Linux 三平台                                                          |
| 移动端 | KMP + CMP（Kotlin Multiplatform + Compose Multiplatform） | 当前只做 Android（无 Apple 设备，无法开发调试 iOS）；选 KMP+CMP 是为日后扩展 iOS 做准备 |

## 4. 功能需求

### 4.1 MVP（第一版）范围

**F1 多供应商大模型接入**
- 首批原生适配 3 种 API 协议：
  - OpenAI Compatible（`/chat/completions`，同时覆盖 DeepSeek 等兼容供应商）
  - Anthropic Messages API
  - Gemini Content Generation API
- 每个用户在服务端独立配置自己的供应商、API Key 和模型列表（互不可见）
- 会话中可随时切换使用哪个供应商、哪个模型（见 F3）

**F2 用户体系（多用户）**
- 用户名 + 密码 + 邮箱注册，登录 / 登出（注册策略细节暂不深究，从简实现）
- 两种身份：**owner**（首个注册用户）与 **normal**（其余所有用户）；owner **当前**不比 normal 多任何权益，仅作为"第一个注册"的标识
- 后续做多用户管理时，owner 会获得管理类权益（如用户管理、配额控制等）——本版本不实现，但架构上为此预留（见技术设计文档）
- 每个用户的对话数据、供应商配置（API Key、模型列表）完全独立、相互隔离

**F3 对话功能**
- 多会话：创建、切换、重命名、归档会话（**无删除功能，以归档制代替**）
- 历史记录：完整保存对话内容
- 流式输出：打字机效果，可中断生成
- 支持 Markdown 渲染、代码块高亮
- **模型配置与会话解耦**：会话不绑定模型，进行到任意一步都可随时切换模型
- **每条 AI 消息记录其来源模型**（供应商 + 模型名），历史记录中可回溯每条回复由哪个模型生成

**F3.5 归档（代替删除）**
- 会话不可直接删除，只能归档；归档后从活跃会话列表消失
- 归档内容整体迁移至 S3 兼容对象存储（R2 / MinIO / AWS S3 等，endpoint 可配置）
- 客户端只保留归档的元数据（标题、消息数、时间范围等），**不直接访问归档内容**
- 支持**解档（恢复）**：归档会话可恢复到活跃列表
- 彻底删除只作用于已归档的会话（删除对象存储中的数据，不可恢复）

**F4 多端同步 + 离线缓存**
- 对话数据以服务端 PostgreSQL 为唯一权威数据源
- 各端在线时实时同步
- 客户端本地缓存历史记录，断网时可浏览已有会话（不能发新消息）

**F5 界面基础：国际化与主题（底层能力，第一版就内置）**
- 所有界面文案走 i18n 框架，代码中不写死文案；首版提供中文 + 英文
- 语言默认跟随浏览器/系统，用户可手动切换，选择持久化
- 主题支持明 / 暗 / 跟随系统三种模式，选择持久化

### 4.2 明确不做（本版本边界）

- 工具调用 / MCP / 插件系统
- 提示词模板 / 角色预设
- 知识库（RAG）
- 语音输入输出
- 图片 / 文件上传
- 消息的分支、编辑重生成
- 会话/消息的直接删除（以归档制代替，见 F3.5）
- 开源协议选型（MVP 完成后再定，不写入本 PRD）

### 4.3 后续版本候选（仅记录，不承诺）

- 工具调用 / MCP 支持
- 提示词模板
- OpenAI 兼容协议接入（作为原生适配之外的补充）
- 消息搜索
- 数据导出

## 5. 非功能需求

- **部署**：Docker Compose 一键部署，包含后端 + PostgreSQL 两个服务；提供 `.env` 配置模板
- **性能**：流式首 token 延迟主要取决于供应商，自身转发不引入可感知延迟（< 100ms 开销）
- **安全**：API Key 存服务端、不下发到客户端；客户端与服务端之间 HTTPS（部署文档指引用户配置反向代理）；密码哈希存储
- **开源要求**：代码结构清晰、有 README 和部署文档，方便他人 fork 和贡献

## 6. 技术架构（初步）

- **后端**：Rust + axum + connect-rust（Connect RPC，proto + buf 契约），ParadeDB（PostgreSQL 18，含 pgvector/pg_search，为后续 RAG 预留）
- **Web / 桌面**：React + 构建工具（Vite），Electron 套壳，一套代码
- **移动端**：Kotlin Multiplatform + Compose Multiplatform，共享业务逻辑层
- **部署**：Docker Compose（后端镜像 + PostgreSQL）

## 7. 里程碑

- **M1**：后端可用 —— 用户体系 + 一家供应商跑通 + 流式对话 API
- **M2**：Web 端可用 —— 完整对话体验（多会话、历史、流式）
- **M3**：桌面端可用 —— Electron 打包三平台
- **M4**：移动端可用 —— Android（iOS 留待未来有 Apple 设备和开发者账号后再做，KMP+CMP 架构已为此预留）
- **M5**：开源发布 —— 文档、部署脚本、仓库整理

## 8. 验收标准（MVP）

- docker-compose up 后，能注册用户并登录
- 配置好供应商 Key 后，Web 端能发起流式对话
- 同一会话中切换模型后能继续对话，且每条 AI 回复能查到它由哪个模型生成
- 同一账号在 Web 端和手机端看到相同的会话列表和历史
- 断网状态下，客户端能浏览已缓存的历史会话
- 三个桌面平台均能安装运行
